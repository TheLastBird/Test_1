# L4 · 架构设计与研发规范编制 · Java 题目（25 题）

> 能级目标：理论笔试正确率 ≥ 90%；能进行中大型系统核心模块架构设计、制定编码规范；掌握不少于 4 类核心机制（JVM 内存模型 / GC 与 JIT / 类加载 / 并发模型 / 分布式一致性 / Spring 与中间件原理 / 推理引擎集成等）；具备 SDK/中间件/算子级开发与优化能力，能制定规范，主导性能治理与代码规范建设，支撑团队规模化工程落地。
>
> 题型分布：单选 8 + 多选 5 + 判断 5 + 简答 4 + 论述 3。
> 合格线建议：客观题正确率 ≥ 90%，简答与论述平均得分 ≥ 80%，案例论述题 ≥ 85%。

---

## 一、单项选择题（每题 1 分，共 8 分）

**1. [L4·架构]** 关于「领域驱动设计（DDD）」中分层架构（接口层、应用层、领域层、基础设施层），下列说法**最准确**的是：
A. 领域层应依赖基础设施层
B. 领域层应保持核心业务规则的独立性，依赖通过端口/适配器从外部注入
C. 应用层应直接持有数据库连接
D. 接口层应承担核心业务规则

**2. [L4·并发架构]** 关于高并发服务的「线程治理」原则，下列说法**最准确**的是：
A. 线程越多越好
B. 应根据 CPU/IO 性质选择合理的线程模型与池化策略，必要时引入异步、Reactor 或协程化框架（虚拟线程）
C. 不需要监控线程
D. 应直接 `new Thread`

**3. [L4·JVM 调优]** 关于大堆 + 低延迟系统的 GC 选择，下列说法**最准确**的是：
A. 一律使用 Parallel GC
B. 根据 SLA 与堆大小评估：低延迟可考虑 ZGC / Shenandoah，吞吐优先可考虑 G1/Parallel
C. 选择 GC 与延迟无关
D. 关闭 GC 即可

**4. [L4·分布式]** 关于「最终一致性」的实现，下列哪一组**更合理**？
A. 本地消息表 + 重试 + 幂等
B. 单纯依赖「ALL OK」的两阶段提交而无补偿
C. 完全靠请求重发
D. 依赖客户端心情

**5. [L4·安全合规]** 在电网安全敏感系统的 Java 服务设计中，下列**必要**的安全要素是：
A. 输入校验 + 输出编码 + 鉴权与授权 + 密钥管理 + 全链路审计 + 日志脱敏
B. 仅前端鉴权
C. 仅在数据库做校验
D. 仅依赖防火墙

**6. [L4·中间件原理]** 关于 RPC 框架（如 Dubbo / gRPC），下列说法**最准确**的是：
A. 仅是简单的 HTTP 调用
B. 涵盖序列化、传输、路由/负载均衡、容错、注册发现、可观测、协议演进等多个核心模块
C. 不涉及序列化
D. RPC 与服务治理无关

**7. [L4·性能治理]** 在制定团队级性能治理规范时，下列哪项**应被纳入**：
A. 关键路径基准（基线 + 报警阈值）+ 压测准则 + 容量评估方法 + 性能问题闭环流程
B. 仅靠开发自觉
C. 由测试单方面决定
D. 不需要基线

**8. [L4·AI 集成架构]** 关于在大型 Java 平台中集成 AI 推理能力，下列说法**最准确**的是：
A. 仅在每个微服务自行加载模型即可
B. 通常构建「推理服务化」层（独立部署 / 异构资源调度 / 批量与微批 / 模型版本管理 / 灰度发布 / 可观测）；Java 服务作为消费方调用，关注超时、重试、熔断、降级
C. 与服务治理无关
D. 不应监控

## 二、多项选择题（每题 2 分，共 10 分）

**9. [L4·架构设计]** 中大型系统中，模块设计应关注：（多选）
A. 高内聚低耦合，明确公共契约（API/Protocol）
B. 错误处理与可观测性内建
C. 失败模式与降级路径
D. 复制粘贴尽量多

**10. [L4·规范编制]** 团队级 Java 编码规范应至少包含：（多选）
A. 命名、目录与包结构、注释规范
B. 异常处理、日志与可观测性规范
C. 并发与资源使用规范（线程池、连接池、缓存）
D. 安全编码（鉴权、加密、敏感数据脱敏）

**11. [L4·分布式]** 关于分布式系统的「弹性」原则，下列说法正确的是：（多选）
A. 故障是常态，应通过重试、超时、熔断、隔离、降级等机制保障可用性
B. 任意服务挂了都不影响主链路（理想化）
C. 多区域、多副本部署可提升可用性
D. 单点强一致即可解决一切问题

**12. [L4·性能治理]** 性能治理体系可包含：（多选）
A. 性能基准库（关键链路 SLA 与历史数据）
B. 自动化压测与回归
C. 慢 SQL/慢调用治理
D. 完全无监控

**13. [L4·AI 集成架构]** 在 Java 平台对接 AI 推理服务时，应关注：（多选）
A. 模型版本管理与契约
B. 限流与配额，避免雪崩
C. 失败重试 + 幂等 + 降级
D. 全链路可观测（QPS / P99 / 错误率 / Token / 资源利用率）

## 四、简答题（每题 5 分，共 20 分）

**19. [L4·架构设计，5 分]** 给出一份「中大型 Java 后端系统」的核心架构分层与职责划分（≥ 4 层）。

> 参考要点：接入层（网关/鉴权/限流）；应用层（业务编排）；领域层（业务规则、聚合根）；基础设施层（持久化、消息、缓存、外部 SDK、AI 推理客户端）；横切关注（日志/监控/安全）。

**20. [L4·并发架构，5 分]** 设计一个高并发 Java 服务的「线程模型与资源治理」方案，至少 5 项要点。

> 参考要点：业务线程池/IO 线程池分离；连接池治理；背压机制；超时与拒绝策略；可观测；异步化（CompletableFuture / Reactor / 虚拟线程）；隔离与限流。

**21. [L4·规范编制，5 分]** 草拟一份团队级「Java 代码规范」目录大纲（≥ 8 章），并对每章用 1 句话说明。

> 参考要点：通用约定 / 命名 / 注释 / 异常 / 日志 / 并发 / 集合与 IO / 数据库与事务 / 安全 / 测试 / Spring 使用规约 / 性能反模式清单。

**22. [L4·AI 集成架构，5 分]** 在 Java 平台规模化对接 AI 推理（DJL/ONNX Runtime/远程推理服务）时，应建立怎样的「调用治理 + 质量保障」体系？请列出 ≥ 5 项要点。

> 参考要点：契约管理；批量与微批；缓存（结果/向量）；多副本/多区调用；降级到规则引擎；预热；版本灰度；熔断 + 限流；可观测；安全合规。

## 五、论述题（每题 7 分，共 21 分）

**23. [L4·架构论述，7 分]** 选择一个你最熟悉的中大型 Java 业务系统（可虚构但需贴近实际），输出一份「核心模块架构 + 关键非功能性需求保障方案」。要求包含：业务问题 → 架构总图 → 关键技术选型（含 Spring/中间件/AI）→ 性能/可用性/安全 → 演进路线 → 风险与边界。

> 参考要点：架构合理；选型理由；性能/可用性/安全/合规均覆盖；演进有阶段；含降级与回滚；含可观测体系。

**24. [L4·性能与规范论述，7 分]** 论述如何在团队中建立「Java 性能治理 + 代码规范」的双轮驱动体系。要求覆盖：现状诊断 → 规范产出 → 工具门禁（如 Checkstyle、SpotBugs、SonarQube、ArchUnit、JFR）→ 培训与认证 → 度量与持续改进。

> 参考要点：闭环可量化；可执行的代码规范条目；门禁与例外申请；典型反模式案例；持续训练与知识沉淀。

**25. [L4·AI 与 Java 工程化论述，7 分]** 在「Java 后端 + AI 推理服务」共存的研发体系中，论述如何制定「面向规模化工程落地」的算子开发与优化规范（可借鉴 ONNX Runtime / DJL 的张量与算子模型）。要求覆盖：能力边界 → 算子接口规范 → 性能基准 → 测试基准 → 版本与兼容性 → 安全与合规。

> 参考要点：算子（Op）输入/输出/形状/精度规范；性能基准（吞吐/延迟/显存）；回归测试集与基准；版本兼容；并行策略（CPU/GPU/批处理）；安全/合规（数据流向、模型来源、密钥）。
