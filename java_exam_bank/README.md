# Java 开发语言与开发框架使用能力 · 个人考试题库

本题库依据《附件 1：测评标准》第 2 章「开发语言与开发框架使用能力测评标准（包括 C、C++、Java、Python）」进行 **Java 语言版** 改编，覆盖 Java 语言基础、并发与 JVM、主流开发框架（Spring / Spring Boot / Spring Cloud / MyBatis / Netty / gRPC 等）以及 Java 生态下的 AI 推理/集成框架（DJL、ONNX Runtime Java、TensorFlow Java），用于检验研发人员个人在 L1–L4 不同能级下的能力。

## 一、能级与考核目标

| 能级 | 能力定位 | Java 维度核心要求 |
|------|----------|-------------------|
| L1 | 任务执行 | 基础理论笔试正确率 ≥ 60%；了解 Java 基本语法（变量、控制流、方法、类、异常）、常见数据结构与集合；了解主流框架（Spring Boot、MyBatis、JUnit；可包含 DJL 等 AI 框架）的基本结构与运行流程；在提供模板情况下完成代码补全（实操通过率 ≥ 70%） |
| L2 | 独立模块开发 | 理论笔试正确率 ≥ 70%；能独立编写函数、类与基础业务逻辑；2 小时限时实操能完成 REST API/推理封装等模块开发，功能正确率 ≥ 80%；能定位和修复常见问题（依赖缺失、空指针、序列化、配置错误等） |
| L3 | 工程化实现 | 理论笔试正确率 ≥ 80%；能进行模块结构设计与并发处理实现；掌握以下核心机制 ≥ 2 类：JVM 内存模型 / 并发模型与锁机制 / 类加载与字节码 / JIT 与 GC / Spring IoC 与 AOP 实现机制 / Netty Reactor 模型；在标准测试环境中完成 ≥ 1 项有效优化（延迟降低 / 吞吐提升 / 内存占用下降）；能在限时案例中独立定位并修复问题 |
| L4 | 架构设计与研发规范编制 | 理论笔试正确率 ≥ 90%；能设计中大型系统核心模块架构；制定编码规范；掌握 ≥ 4 类核心机制（JVM 内存模型 / GC 与 JIT / 类加载 / 并发模型 / 分布式一致性 / Spring 与中间件原理 / 推理引擎集成）；具备 SDK/中间件/算子级开发与优化能力，能制定规范，主导性能治理与代码规范建设，支撑团队规模化工程落地 |

> 说明：标准原文以 Python 为例，本题库将 L3/L4 提到的「张量维度传播规则、精度压缩/量化、计算图执行、并行策略」等 AI 框架机制，按 Java 语境对应替换为：JVM 内存模型与字节码、并发与锁、类加载与字节码增强、GC/JIT、Spring 容器与 AOP 代理、Netty/Reactor、分布式一致性，以及 DJL/ONNX Runtime Java 中的张量与推理执行机制。

## 四、考核范围速览

- **Java 语言基础**：基本类型与自动装箱；流程控制；面向对象（封装/继承/多态）；接口与抽象类；泛型与协变；异常体系；集合框架；Stream 与 Lambda；I/O 与 NIO；反射与注解。
- **JVM 与并发**：JVM 内存区域与对象布局；类加载机制与 ClassLoader；GC 算法与常见收集器（G1、ZGC、CMS、Parallel）；JIT；JMM 与 happens-before；synchronized / volatile / final；`java.util.concurrent`（Lock、Atomic、线程池、并发集合、CompletableFuture、Fork/Join、ThreadLocal）。
- **主流开发框架**：Spring Core（IoC、AOP、Bean 生命周期）；Spring Boot（自动装配、Starter、配置）；Spring MVC / WebFlux；MyBatis（动态 SQL、缓存、插件）；Spring Cloud（注册中心、配置中心、熔断限流、网关）；Netty（Reactor 模型、Pipeline、ByteBuf）；gRPC / Dubbo；JUnit 5 / Mockito；Maven / Gradle 构建。
- **数据与中间件交互**：JDBC、连接池（HikariCP）、Redis（Jedis/Lettuce）、Kafka、MQ；事务与一致性。
- **Java 与 AI 框架集成**（L3+ 重点）：DJL、ONNX Runtime Java、TensorFlow Java；模型加载、张量构造、推理执行、JNI/Foreign Function 调用；性能优化（线程池、批处理、显存/内存复用、零拷贝）。
- **工程化能力**：分层与领域建模；并发设计；性能 profiling（JFR、Async-Profiler、Arthas）；线上故障排查；代码规范与质量门禁；可观测性（Metrics、Logging、Tracing）。

## 五、使用方式

1. **个人自评**：按目标能级抽取对应章节，60 分钟闭卷完成笔试，再用 90–180 分钟完成实操题。
2. **晋级考核**：「目标能级笔试 ≥ 该能级合格线 + 至少 1 道实操题得分 ≥ 80%」方可晋级。
3. **能级判定**：连续两个能级笔试均合格但实操未达标者，按低能级判定。

> 详细计分与晋级路径见 `07_评分标准与晋级路径.md`。

## 六、命题原则

- **分级清晰**：每题在题干末标注能级与考核维度，如 `[L2·并发]`、`[L3·Spring 原理]`、`[L4·架构设计]`。
- **可校验**：客观题答案唯一；主观题给出「评分要点 + 关键扣分项」。
- **贴近研发**：题干优先取材自代码片段、API 设计、性能问题排查、Spring 启动失败、并发踩坑、JVM 故障定位等真实场景。
- **覆盖框架**：每个能级均覆盖语言、并发/JVM、主流框架、构建/工程化四个维度；L3/L4 增加 AI 框架集成与架构治理。
